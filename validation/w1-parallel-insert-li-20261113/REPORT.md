# W1 — 多行 INSERT 的并行解析与打包

基线：`19143e9`（T1+T2+T3 集成）。改动：`src/engine.cpp` 的 INSERT 执行路径。

## 问题

写入路径 100% 串行。perf 采样（10k 行 / 100 批）显示写入侧 ~40% 时间在文本解析：
`std::from_chars` 22.5% + `vector_literal` 17.2%，另有 `pack_row` 8.4%。
查询早已并行，写入没有。

## 机制

- `convert()` + `pack_row()` 是逐元组的纯计算，可以并行；`store_.get`（重复主键检查）
  与 `store_.put`（journal 追加）必须保持语句内顺序，仍串行。
- 按 256 行分块：块内并行准备 `(key, packed_bytes)`，块内按序应用。
  分块上界避免超大 INSERT 把常驻内存翻倍。
- 并行门槛 16 行；宽度与池容量取小，1 CPU 时完全走原路径。
- worker 内抛出的类型错误在应用任何一行之前回传主线程，语句整体失败，
  由既有语句级截断保证原子性（比原来更早失败，语义不变）。

## 实测（2 CPU cgroup，10k 行 / 100 批，1000 次查询，20 对交替）

| 指标 | 配对中位 | 胜率 | 区间 |
| --- | ---: | ---: | --- |
| 写入耗时 | **+6.07%** | **19/20** | −3.21% … +21.84% |
| 查询耗时 | −2.06% | 8/20 | −22.85% … +12.78% |

查询侧未改动该路径，−2.06%/8-20 属噪声。

## 结论

保留。19/20 胜、中位 +6.07% 明显高于该机写侧噪声（同二进制对照中位 ±1.3%、单对 ±13%），
且不改变任何可观察语义。
