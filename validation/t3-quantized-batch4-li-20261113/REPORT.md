# T3 — int8 粗筛跨 4 行批处理

基线：T2 提交 `perf/t2-survivor-refine-li-20261113`
改动：`src/exact_cache.hpp`（新增内核）、`src/engine.cpp`（两处粗筛调用点）、
`tests/test_exact_cache.cpp`（内核等价测试）

## 问题

32 行只是外层批次：int8 内核每个批次仍然**逐行调用**（`noinline`），每行都要重新加载 query
的 16 个 int16 编码，并且每次调用只维护一条累加链。粗筛占查询时间的 36.7%（perf 实测），
函数调用与 query 装载的开销摊在每行上。

## 机制

新增 `quantized_squared_distance4_avx2(r0,r1,r2,r3,query,dim,out[4])`：

- 每 16 维迭代只装一次 query 向量，四行各自一条独立整数累加链，共享该 query 寄存器。
- 四行的归约结果分别用 64 位宽无关的整数加法合并（整数加法可交换/结合，与原内核同值）。
- 维度尾部（`dim % 16`）保留标量逐维累加，与原内核一致。
- 包装 `quantized_squared_distance4(cache, rows[4], query, out)` 负责行指针换算；
  非 AVX2 编译目标回退到四次单行调用。

调用点：连续路径按 `offset += 4`（批次为 8 或 32，均为 4 的倍数），
候选列表路径同样按 4 行取 `batch[offset..offset+3]`。

不变：量化范围、`D <= 8192` 与整数不溢出条件、粗筛只做保守排除、最终结果仍由 double 精算。

## 实测（2 CPU cgroup，3000 次查询，10k×128D，20 对交替）

| 指标 | 配对中位 | 胜率 | 区间 |
| --- | ---: | ---: | --- |
| 查询耗时 | **+5.31%** | **17/20** | −3.33% … +16.97% |
| 写入耗时 | +3.09% | 13/20 | −9.46% … +12.62% |

## 正确性

`test_exact_cache` 新增 `test_quantized_four_row_kernel`：维度 1/7/16/17/64/127/128/129
（含标量尾部），随机编码，逐行对比 4 行批处理与 4 次单行调用的返回值，要求**完全相等**。
CTest 9/9 通过。

## 结论

保留。17/20 胜、中位 +5.31% 超过该机噪声（同二进制对照中位 ±3%），且与 T2 同为纯计算优化，
不改变任何可观察语义。
