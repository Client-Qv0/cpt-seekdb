# 3.3 公开规模的本机性能验证

日期：2026-11-09。结果用于本机开发，不是官方性能分、名次或正式准入结论。

## 已完成

题面公开的默认规模为 10,000 条 128 维记录、100 条一批自动提交、1,000 条 Top-10 查询，其中 500 条带普通列等值过滤。本轮以仓库已有的本地种子生成器执行这一规模：种子 3179 连续三轮，另用 9143、27183、2468 各一轮，共六轮独立容器和独立数据目录。该生成器是仓库本地工具，不能称为组织方冻结的正式生成器。

六轮全部满足本地断言：每轮 100 批写入的确认条数正确，1,000 条计时查询加 11 条首次/预热查询全部通过独立 FP32/FP64 穷举参考；每轮有过滤和无过滤的平均、最低 Recall@10 均为 1.0。每轮在计时容器结束后重新启动一个容器，读取并核对全部 10,000 条记录的 ID、过滤列与全部 128 个 FP32 分量。查询的数量、去重、过滤、每个距离、TopK 成员及顺序均被核对。`offline-audit.json` 从保存的原始 SQL、查询响应、完整回读文件重新计算并检查全部六轮。

另一次非计时恢复测试在 100 批写入全部确认后以 Docker SIGKILL 终止数据库：容器退出码和 OOM 状态确认是主动强杀，重启后完整核对 10,000 条记录通过（`crash-recovery.json`）。这不等于断电测试，也不覆盖提交响应尚未收到的所有边界。

生产 Dockerfile 在本机实际构建成功；镜像内 `/app/minivectordb` 与本机 Release 二进制 SHA-256 均为 `78996ec9a6d15c5357b5111a4fd78ed28bf1cde174538dee81ae5de1b2daf26c`。独立桥通过镜像的实际 ENTRYPOINT 跑公开样例，20 例、95 条 SQL 全部通过（`public-docker-cases.json`）。ANN 指令仍显式回退精确检索，错误语义码及官方 stdin/stdout 协议未验证。

## 三轮本机耗时和内存

种子 3179 的每轮依次创建空表、执行 100 批写入，执行一次首次查询和 10 次固定预热，然后计时 1,000 条查询；结果收集包含在对应计时段，独立 oracle 计算和完整重启回读在计时之外。写入和查询在同一测量容器内依序进行，以下内存是该容器从启动到各采样时点的 `memory.peak`。

|---|---:|---:|---:|---:|
| 1 | 0.528331 | 1.148673 | 7,389,184 | 13,914,112 |
| 2 | 0.504302 | 1.185950 | 7,389,184 | 13,914,112 |
| 3 | 0.499873 | 1.193205 | 7,503,872 | 14,041,088 |

三个扩展种子是正确性交叉验证，不合并进上述三轮中位数。各轮使用实际 cgroup v2，读取并检查 `memory.max=134217728`、`memory.swap.max=0`、`cpu.max=200000 100000` 和本机允许 CPU 集中的两核；无容器 OOM。结果属于本机特定配置，不声称这些是官方最终限额。所有原始容器记录、预热和查询结果及检查结果保存在各 `seed-*/round-*` 中。

## I/O 边界

数据目录放在本机 WSL ext4 的任务专属 `/var/tmp` 子目录，测试和输出日志放在 E 盘。`writeback-calibration.json` 记录独立容器对该文件系统同步写入 16 MiB，所见 cgroup 的设备 `8:48` 写计数增加 16 MiB。三轮主负载的原始 `io.stat` 快照位于 `metrics.json` 和各 `run.json`；例如首轮首个存活采样的 `wbytes=4096`、查询后 `wbytes=6049792`。

该设备与 WSL 其他工作负载共享，并非评测专用数据设备；采样从容器启动后开始，没有保留容器直到独立完成最终文件系统回写同步，也没有建立平台同口径的冷缓存及 I/O 带宽控制。因此这些计数只能作为本机观测，不能作为正式物理 I/O B 或综合指标 E。首次采样之前的启动 I/O 也可能遗漏。没有执行全局清缓存。

## 当前缺口

- 官方性能驱动、正式数据生成器及种子、资源与时间上限、缓存流程、参考实现和固定 T/B/M 基线仍未获得；不计算 E、排名或 40 分制成绩。
- 正式 MySQL 29 例准入尚未通过验证。公开题包本身声明只有 20 例、95 条 SQL，且不包含完整通信驱动。当前镜像仍使用显式 `--dev-protocol`，不能声称兼容正式 stdin/stdout 协议。
- Dockerfile 的 Ubuntu 标签和 apt 包未完整锁定；这次构建的镜像 ID、日志及可执行文件哈希已保存，但不承诺以后联网重建逐字节一致。
- 这里没有实现真正 ANN；题目允许 exact 模式，但正式模式切换接口仍未知。旧 UPDATE 慢例也不在本轮调查范围。
- 未提交或推送代码，未提交正式评测。代码及全部新证据均留在当前个人 worktree 供用户审阅。

## 复跑与证据

通用用法见 `tests/README.txt` 的 “Local performance-shape and persistence validation”。本机可用 `bash validation/benchmark-public-hmy-20261109/run_public.sh <seed> <rounds> <new-output-name>`；脚本拒绝覆盖同名证据。必须保证实际镜像、可执行文件和生产源码清单一致，输入 NumPy 仅供参考计算。当前 WSL Git worktree 对 Linux Git 的跨盘 `.git` 路径不兼容，查看 Git 改动请使用 Windows Git。

`frozen-tools/` 是主要三轮及前两个扩展种子完成后、随后改动驱动前保存的工具副本；这几轮当时没有记录驱动源码哈希。2468 轮记录了运行时的全部工具 SHA，`driver-2468-as-measured.py` 在后续仅改变 Docker 临时匿名卷清理后重建，并验证与当时记录的 SHA 一致。当前驱动另外检查计划轮次是否全部完成，并校验运行前后驱动哈希；不能把这些后加的保护写成早期三轮当时已具备。
