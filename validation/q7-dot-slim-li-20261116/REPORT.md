# MiniVectorDB 性能续测：LTO、7-bit 点积、FP32 编码

本轮以日志映射提交 `9f358eaedd79b1921c137891b252e8341fe333e0` 为基线。每轮查询 10k×128、100 次自动提交、1000 条正式 JSONL TopK10，过滤与无过滤各半；本机 WSL2/ext4，数据库 cgroup 独立。耗时差相对同轮两份基线的几何平均，负值更快。统计区间是对配对中位差的描述性 bootstrap 结果。当前没有平台预检或正式成绩。

| 项目 | 结果 | 取舍 |
|---|---|---|
| GCC 13.3.0 Release LTO，20 轮 | 混合查询 +1.34%（+0.40% 至 +2.20%），写入 +5.13%（+3.69% 至 +6.59%） | 否决；未修改 Dockerfile |
| 映射 + 7-bit 点积，首轮 20 对 | 混合 −3.63%（−5.00% 至 −2.28%），16/20；写入 +0.68% | 继续复验 |
| 映射 + 7-bit 点积，确认 20 对 | 混合 −3.12%（−3.85% 至 −1.05%），15/20；过滤 −0.63%，无过滤 −4.75% | 通过混合查询中位 −3% 门槛 |
| 7-bit 单独写入，20 对 | −1.01%（−3.40% 至 +1.14%） | 排除本轮写入中位退化超过 3%；前两次伴随查询的写入区间上界分别 +3.52%、+3.88% |
| FP32 按行指数编码 | 三种子各少写 13.10%；单核精算序列回放增加 69.17–70.17 ms，远超约 3.6 ms 预算 | 否决当前解码方式；仅探针，未改日志格式 |

7-bit 只改变整数粗筛，沿用精确 FP64 距离和主键排序。可用性检查覆盖普通和偏置码；查询码落在 ±64 以外、但仍处于原整数码域时，从同一份偏置行码以无符号方式读取并减去偏置，保持映射视图。整表没有双份行码。逐项检查覆盖字节 128、查询码 65 和尾批。

确认轮每个候选均存在只读日志映射、计数器记到 1,009 次偏置粗筛查询。对同时测的旧比赛基线 `f9a61047`，峰值内存中位少 4.75 MiB，最少也少 4.38 MiB；相对映射基线的中位差为 0 MiB。两轮完整有序 JSONL 回包摘要均相同，未观察到物理 I/O 增加。独立写入对照每个版本同样完成 100 次自动提交。

Release CTest 9/9、压力 21/21、优化 17/17、正式 JSONL 协议检查、858 条差分、公开 20 例（本地桥接）通过。128 MiB / 零 swap 下完成 checkpoint 真正换代、SIGKILL 恢复、独立距离位验证，峰值约 26.24 MiB，无 OOM。

压缩探针在独立 cgroup 以每批一次 RWF_DSYNC 写相同批次。raw/packed 文件大小约 5.53 MB / 4.75 MB；目标设备实际写入 5,939,200 / 5,160,960 B。位级测试 4,096 行，涵盖两种记录编码、截断、负零、次正规数和有限极值。读取探针跟踪已验证映射版的精算行访问后做单核原样回放，比较结果准确一致；回放不等同于完整 SQL 或正式评测。

首个拟提测版本仍为只含映射的 `9f358eae` 加队友冻结的 Prompt。7-bit 是后续独立候选。素材未冻结前不组成正式提交；本机没有 Docker/Podman，未运行锁定镜像或平台预检。比赛分支未改动。
